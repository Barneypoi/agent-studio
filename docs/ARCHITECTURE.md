# 实现结构

- `game/main.gd`：Godot 原生界面、可调宽度的房间与对话侧栏、人物编辑、技能与任务操作。对话面板按任务保留输入草稿和阅读位置，与场景共用主视口；设置类窗口使用独立弹窗。
- `game/conversation_view.gd`：按消息 ID 更新左右气泡，支持文本选择、完整对话复制和阅读位置保留；工具记录继续使用独立文本视图。
- `game/session_import_view.gd`：本机会话列表、分页与筛选、历史预览和导入选择；默认复制，只在最终点击时提交导入。导入请求标识防止连续点击重复创建。
- `game/world.gd`：绘制俯视像素场景、角色移动与入座/离座状态、地图交互。角色在可行走的椅侧入口结束寻路，再过渡到坐姿；坐姿、名称和点击区域共用显示位置，椅背独立绘制以正确遮挡人物。
- `game/leisure.gd`：根据家具位置与方向生成休闲入口及沙发座位，选择可达且未占用的活动。`world.gd` 管理走近、使用、到时离开；真实任务优先中断活动，布局变化和角色移出清除占用。活动不写入任务或存档，不连接桥接。
- `game/social_life.gd`：仅在场景内运行的碰面、短聊、挥手和小动作状态机。计时器控制间隔，预设短句随书架、茶桌或音乐设施变化；不读取提示词、回复或私人数据，不使用网络、桥接或 MCP。双人互动预约同一房间的可达空地，暂时保留旁听伙伴的设施占用；工作状态变化、角色移出和布局编辑会释放双方。一次任务完成事件可触发附近空闲伙伴鼓励，恢复旧完成状态不重播。
- `game/pixel_art.gd`：自绘角色和家具，所有像素美术均包含在源码中。
- `game/decor_art.gd`：新增设施与装饰的像素绘制、动态水景和唱片；地面轮廓随朝向旋转，竖直部分保持直立。
- `game/room_themes.gd`：六种地板与三组主题房间的布置数据。主题只在放置预览中携带 `template`；确认后保存普通房间和独立家具，修改房间不会重复生成内容。
- `game/furniture_card.gd`：布置面板中的像素家具缩略图、尺寸与说明；分类只影响选购展示。
- `game/studio_model.gd`：房间/家具数据、连通性校验、寻路、撤销与原子存档。
- `bridge/server.mjs`：Node.js 标准库实现的本地桥接，不依赖 npm 包。
- `bridge/session-imports.mjs`：读取原生会话、转换历史和注册导入任务；支持传统完整历史及 `thread/turns/list` 分页。只转换消息、文件和工具记录，不重放旧工具与委派事件。
- `bridge/approvals.mjs`：将原生审批选项转换成带授权范围的界面选项；提交时按待审批请求重新解析选择，拒绝无效选项，不接受前端自拟规则。
- `bridge/conversation.mjs`：保存有序的用户/角色消息，按 `clientUserMessageId`、原生 turn/item ID 合并回显、流式输出和完成事件；失败的追加输入撤回。首次打开旧任务通过 `/conversation` 读取本机原始历史迁移，无法恢复时展示带说明的旧版记录。

桥接仅监听 127.0.0.1 的随机端口，用每次启动生成的随机 token 鉴权，并拒绝来自浏览器 Origin 的请求。Godot 使用 HTTPRequest 发送指令并轮询快照；桥接通过 JSONL RPC 连接 Codex App Server。

对话收尾使用桥接 `/finish`，在 `tasks.json` 保存 `endedAt`，保留原执行状态、结果和时间顺序。界面将已结束的当前对话映射为待命，历史仍可读；新一轮执行事件会清除结束标记。负责人及后代全部处于终态后才可一起结束，此操作不调用 Codex。

子任务的收尾负责人默认取 `parentId`。直属委派者成功完成原生 `closeAgent`，或自身交付进入 `completed` 后，桥接释放已处于终态且没有活动后代的子任务，保存 `endedAt` 和 `endedBy`。单独的子任务完成事件会先等待委派者收尾；关闭中的请求、失败的关闭和无关任务不能触发释放。关闭事件按 turn/item ID 去重，原生委派关系在发现时核对。原生关闭用于实际子 agent 生命周期，交付后的自动收尾用于工作室角色与完成标记。

收尾归属由创建时的 `parentId` 决定：主任务由用户负责，子任务由直属委派者负责。查看、补充和转达消息都不转移责任。`completionOwnerId` 作为展示字段随创建关系保存；启动时纠正旧版由消息日志推断出的错误归属，保留任务结果和历史。界面隐藏子任务的用户结束按钮，标注具体委派者。

角色档案与任务实例分开。每个任务保存创建时的外观/职责/技能快照。新任务启用当前角色的技能配置，并用真实 `skill` 输入调用；配置不写入用户全局 config.toml。团队模式将其他角色的职责和技能交给负责人，用原生 subagent 执行。`thread/started`、`collabAgentToolCall` 和 `subAgentActivity` 用于发现子任务。

状态来源是实际协议事件。任务结束区分 completed、failed、interrupted；完成含义是执行结束，仍需用户验收。用户审批和问题逐条转回原来的 RPC 请求。仅 `idle` 角色会使用休闲设施；休闲和散步均是本地环境动画，不改变真实任务状态或调用模型。主题扩建将全部家具加入通路校验，整体提交为一个撤销步骤；原有存档不会自动添加新房间或装饰。

审批优先使用 `availableDecisions`，旧版本未提供时按协议支持的决策和建议规则构建选项。规则授权原样回传 `acceptWithExecpolicyAmendment` 或 `applyNetworkPolicyAmendment`；任务会话授权使用 `acceptForSession` 或权限请求的 `scope: session`。规则保存交由 Codex 完成，应用不另建绕过审批的白名单。停止任务只拒绝待审批请求，不建立持久拒绝规则。

数据：`studio.json` 保存布局与角色；`tasks.json` 保存消息/日志/任务快照；`codex-state/` 和 `codex-logs/` 是桥接管理的本地运行数据。任务消息和工具结果属于项目数据，不打包分享给其他人。

Codex App Server 有版本差异，桥接基于本机 CLI 生成的协议核对。恢复子 agent 时先恢复其父任务；直接输入若不被后端允许，会通过父 agent 转达，界面明确显示转达状态。角色映射优先使用原生 task_name 和委派中的档案标记，并处理迟到的角色信息。游戏通过实际 HTTP 连接检查已有桥接，避免依赖 macOS 上仅适用于子进程的 Godot PID 查询。端到端验证状态见 VALIDATION.md。

## 本机会话导入

桥接按存储来源维护两个独立 App Server 客户端。已有工作室任务继续使用原来的 `sqlite_home`；导入浏览器按需连接原生默认索引，以读取桌面端保存的分页历史。任务与新子任务保存 `nativeStore`，恢复、消息、停止、审批均回到对应进程；待审批请求的标识也区分来源。原生数据、登录信息和配置不复制进项目。

`GET /sessions` 只查询原生主会话列表，支持标题、目录、归档和游标；`GET /session-preview` 只读取近期历史。`POST /import-session` 完整读取文字记录，绑定角色并即时保存。原会话模式不调用 resume；复制使用 `thread/fork` 并设置 `deferGoalContinuation: true`，防止继承目标自动执行。两种模式都不发送模型回合，并保存 `endedAt` 和「尚未继续」标记。活动会话和委派子会话不能导入，角色准备锁避免并发占用。

导入任务首次或再次明确续聊前重新读取原生历史，并检查活动状态和目录；目录在其他客户端改变时拒绝继续，提示重新复制导入。随后恢复任务，按工作目录写入沙箱和正常请求审批方式发送新回合。角色绑定不覆盖旧会话指令。副本只复制对话，不复制或隔离项目文件；原会话模式不提供跨客户端的全局执行锁，用户应避免同时操作。

旧委派只作为日志保存，防止导入时重建历史中的角色或执行旧工具。历史里的客户端专用工具会显示依赖提示；新的 `item/tool/call` 若依赖工作室不支持的客户端工具，明确返回失败，供模型改用可用工具或向用户说明。通用 MCP 与 Skills 仍由原生 Codex 提供。多媒体附件仅显示占位提示；超出当前历史读取上限时显式报错，不悄悄截断后宣称完整导入。
