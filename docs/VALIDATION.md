## 联调中修复的问题

- macOS 外部桥接进程不能用 Godot 子进程 PID 查询判断存活，已改为实际连接检查，避免重复启动。
- 原生子 agent 的随机昵称先于角色信息到达，已支持后续绑定及稳定档案标记。
- 恢复原生子 agent 必须先恢复父任务；不支持直接输入时，由负责人转达。
- 并发审批按序呈现；负责人已结束后仍可停止活动的后代任务。
- 恢复较早创建的任务时，角色优先显示当前活动任务；最终回复优先显示可读的完成结果。

## 对话结束更新（2026-09-09）

2026-09-09 补充「结束对话」：完成、失败或停止的任务可结束对话，`endedAt` 单独持久化，不改写执行结果，也不会把更早的历史任务提升为当前任务。原生子 agent 全部停止或完成后可随负责人一起结束。新的工作事件会清除结束标记，恢复角色状态。

本次变更通过 26 项 UI 检查和既有离线协议回归，覆盖结束后的即时落盘、重启保留、继续后重新通知、活动子任务拒绝结束及终态父子任务一并结束。另使用导出的资源包和应用引擎，在离线桥接替身上实际点击「结束对话」与「发送补充 / 继续」，11 项窗口交互检查通过。截图为 `previews/conversation-end-action.png` 和 `previews/conversation-ended.png`。新接口不调用 Codex；本次未重复真实模型联调，原真实验收记录仍对应此前的桥接版本。

修复角色工作时只站在电脑前的问题：新增四向坐姿、工作时打字和入座/离座过渡。工位与椅子仍属于不可穿行的家具区域，寻路在椅子侧的空地结束；坐姿采用显示位置过渡，不修改地图通行规则。角色点击区域随坐姿移动。

## 记住审批更新（2026-09-09）

根据本机 Codex 0.153.4 生成的协议和 [官方 App Server 审批说明](https://learn.chatgpt.com/docs/app-server#approvals)，接入命令规则、域名规则与任务会话授权。界面展示「始终允许」及其作用范围，命令审批优先遵循 `availableDecisions`。前端只提交选项 ID；桥接根据尚未结束的原始请求取出对应的协议结果，不接受前端传入任意规则。

既有离线桥接回归通过，并覆盖命令前缀精确回传、域名允许规则、文件修改与权限请求的会话范围、不可用选项拒绝、请求保持待审批、一次性允许及停止时不创建永久拒绝规则。26 项既有 UI 检查通过。打包资源与应用引擎配合模拟桥接，21 项窗口检查通过，实际点击「始终允许」和「始终允许（本任务）」，核对发出的决策并确认审批解除。截图为 `previews/approval-rule.png` 和 `previews/approval-session.png`。

此次测试不调用真实 Codex、不建立真实授权规则，因此未重复验证后端规则跨重启生效；原真实审批验收仍对应此前版本。`BUILD.json` 分别记录当前桥接入口、审批模块与游戏包哈希。

## 复现离线检查

在源码根目录执行，将 godot 和 node 替换为本机可执行文件：

```sh
AGENT_STUDIO_TEST_DIR=/tmp/agent-studio-model-test godot --headless --path game --script tests/test_model.gd
godot --headless --path game --script tests/test_world.gd
AGENT_STUDIO_DATA=/tmp/agent-studio-ui-test godot --headless --path game --script tests/test_ui.gd -- --no-bridge
node bridge/tests/integration.mjs
```

UI 测试要求数据路径含 ui-test，会清除该独立测试目录中的 studio.json。离线测试均不调用模型。真实联调脚本属于此次授权的工作区验收材料，不会在游戏启动时自动执行。
